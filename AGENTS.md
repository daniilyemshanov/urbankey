# Правила работы с проектом

1. Перед значимыми изменениями прочитайте `docs/project-knowledge/AI_CONTEXT.md`; затем откройте профильный документ.
2. Сохраняйте существующую архитектуру, контракты, дизайн и бизнес-логику, если задача прямо не просит иного.
3. Ищите существующие функции и маршруты перед добавлением новых; не дублируйте их.
4. Никогда не выводите, коммитьте или переносите секреты в клиентский код. Не открывайте `.env` ради общего аудита.
5. Не применяйте SQL к production, не меняйте внешние настройки и не выполняйте deploy/push без явного разрешения.
6. После подходящих изменений запускайте тесты, build и lint для изменённых файлов; фиксируйте ограничения окружения.
7. Обновляйте профильную документацию при изменении API, базы, интеграций или архитектуры.
8. Значимые изменения записывайте в `docs/project-knowledge/CHANGELOG_AI.md`.
