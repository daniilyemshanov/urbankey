# URBAN KEY — итоговый SEO / Local SEO / GEO отчёт

**Дата:** 27 ноября 2026 · **Сайт:** https://urbankey.uz · **Охват:** Ташкент · RU / UZ / EN

## Короткий итог

Архив содержит предыдущий SEO-аудит и deployment notes от 9 ноября 2026. В нём уже реализованы серверные HTML-метаданные для ключевых маршрутов, sitemap активных объявлений и непустых районов, статусы 404/503 при проверке объектов и фильтрация проданных объявлений через публичные SQL VIEW. Полный Git diff недоступен: ZIP не содержит `.git`, а текущая рабочая папка не является checkout репозитория. Секретные файлы архива не открывались.

## Что обнаружено и исправлено

1. **robots.txt не различал OpenAI-ботов.** Теперь OAI-SearchBot разрешён для доступных публичных страниц, GPTBot отдельно запрещён для всего сайта. Правила чувствительных/закрытых маршрутов повторены в группе SearchBot. Это соответствует разным ролям поиска и обучения в [официальной документации OpenAI](https://developers.openai.com/api/docs/bots). Доступ CDN/WAF по сети и фактические запросы робота не проверены.
2. **GA4 page_view отправлял query и мог передать PII из URL.** Теперь параметр маршрута принимает строку и объект, а `page_path` и `page_location` строятся только по origin и pathname без query/fragment. Существующая очистка PII в остальных событиях сохранена. `generate_lead` отправляется только после успешного ответа API; телефон и Telegram учитываются как события без номера/имени пользователя.
3. **SEO-текст страниц районов жилой недвижимости упоминал аренду квартир.** В RU/UZ/EN метаописания и intro исправлены на продажу квартир; существующие маршруты и фильтры не затрагивались. Коммерческая аренда оставлена.
4. **Title общего каталога обещал только покупку.** Title синхронизирован в серверном SEO-контенте и локалях RU/UZ/EN, чтобы отражать смешанный каталог.
5. **Контактный SEO-текст заявлял адрес офиса**, который не подтверждён предоставленными данными. Утверждение убрано в серверной и клиентской локализациях.

## Что уже реализовано и повторно не переделывалось

- Серверный HTML shell с title, description, canonical, hreflang, OG/Twitter, содержимым H1 и JSON-LD для основных публичных страниц и активных объявлений.
- Sitemap с языковыми вариантами, доступными переводами объявлений и районами, в которых есть инвентарь; сбои базы ведут к 503, а не к неполному sitemap.
- Проверки существования объектов для 200/404/503; проданные записи должны исключаться публичными VIEW. Это поведение описано в deployment notes, но production VIEW здесь не проверялись.
- `RealEstateAgent`, `WebSite`, `BreadcrumbList`, `RealEstateListing`; `sameAs` указывает Instagram, Telegram и Facebook из исходного кода. Профили и право собственности на них нужно подтвердить.
- GA4 с SPA page_view, `generate_lead`, формами, телефонными и Telegram-кликами. GSC, GA4, Яндекс.Вебмастер и качество лидов по аккаунтам не проверялись.
- 12 районов и два типа недвижимости реализованы прежним изменением. Не создавались новые малосодержательные страницы.

## Local SEO / GEO возможности

- Добавить подтверждённые NAP (название, публичный адрес, телефон) в единый источник и сверить сайт, GBP, Яндекс, 2GIS и каталоги. Не помещать адрес в Schema до подтверждения, что это публичный клиентский адрес.
- Сохранить `sameAs` только для подтверждённых официальных профилей; добавить реальные карты и каталоги после проверки владельцем.
- Страницы районов уже имеют RU/UZ/EN. Дальше развивать их фактами сотрудников и наличием объектов: состав предложения, ориентиры/транспорт с источником, проверяемые особенности конкретных домов. Не публиковать выдуманную динамику цен, сделки или универсальные шаблоны.
- Приоритет экспертных материалов: чек-лист проверки квартиры перед покупкой; документы и этапы сделки в Узбекистане с юридической проверкой; как сравнивать районы и маршрут/инфраструктуру; критерии выбора коммерческого помещения под сценарий бизнеса; разбор реального кейса только с подтверждёнными данными и согласием клиента.
- Для каждого материала редакционное ТЗ: эксперт-автор и должность, фактическая основа/ссылки, дата публикации и пересмотра, ограничения и конфликт интересов. До получения этих сведений статьи не выдумывать.

## Первые действия владельца

1. В обычном checkout проверить `git status`/diff и запустить `npm run test:seo`, `npm run test:all`, `npm run build`.
2. После релиза в preview проверить статусы 200/301/404/503, HTML RU/UZ/EN, canonical/hreflang и sitemap; затем владелец принимает решение о production deployment.
3. Предоставить read-only GSC/GA4/Yandex данные и доступы к Search Console/Webmaster; проверить подстановку `page_location` и успешные лиды в GA4 DebugView.
4. Проверить историю исходного Git checkout и ранее переданные архивы на секреты; ротировать ключи, если они действительно попадали в историю или передачу.
5. Подтвердить публичное название, телефон, адрес (если он открыт клиентам), официальный Instagram/Facebook/Telegram и профили на картах.
